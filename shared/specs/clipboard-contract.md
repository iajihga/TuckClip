# TuckClip clipboard behavior contract

This document defines behavior shared by the native macOS client and the
Windows client. It is a product contract, not a requirement that Swift and C#
share compiled source.

## Capture

- TuckClip is local-only. Capturing, searching, and pasting must not require a
  network request, account, telemetry SDK, or cloud service.
- A clipboard update is normalized into one of `text`, `link`, `image`, or
  `files`. When several portable representations are present, the priority is
  files, image, then text/link.
- Text and links are limited to 128 KiB of UTF-8. Images and the encoded file
  list are limited to 25 MiB per capture. Oversized content remains in the
  system clipboard but is not persisted.
- A standalone `http`, `https`, `ftp`, or `mailto` URL is classified as a link.
- Standard private, transient, password-manager, and high-confidence private
  key markers are filtered before payload persistence.
- TuckClip-generated clipboard writes carry an internal marker and must not be
  captured as a new item.

## Identity, order, and limits

- A fingerprint is lowercase SHA-256 over `UTF8(kind) + NUL + payload`.
- File payloads join normalized paths with NUL. Images use their canonical PNG
  bytes. Text and links use their exact UTF-8 bytes.
- Capturing an existing `(kind, fingerprint)` updates its timestamp, source,
  and copy count instead of adding a second record.
- Results are sorted by most recent update, then creation time, then stable ID.
- Search is case-insensitive and treats diacritics and full-width forms as
  equivalent. Every whitespace-separated query token must match.
- Retention and maximum-count pruning never remove pinned items. Unpinning
  immediately reapplies both limits.
- A corrupt history database enters read-only protection. It must never be
  replaced with an empty database and its image blobs must not be inferred to
  be orphans.

## Paste transaction

Selecting an item always writes it to the system clipboard first. Automatic
paste is an optional second phase:

1. Snapshot the target application/window before showing TuckClip.
2. Write the chosen value and record the system clipboard receipt/sequence.
3. Hide the current panel session.
4. Restore and positively verify the original target.
5. Recheck that the clipboard receipt is unchanged immediately before posting
   the paste shortcut.
6. Post exactly one platform paste shortcut.

If the panel is closed and reopened, the old session cannot close the new panel
or post input. Permission, focus, integrity-level, cancellation, and clipboard
race failures all degrade to copy-only; input must never be sent to an
unverified target.

The receipt identifies the single write initiated by the user's selection; it
does not restrict which history item may be selected. On Windows, the stable
internal-write marker remains separate from a per-write cryptographically
random `io.github.iajihga.TuckClip.WriteReceipt.v1` binary envelope. The
envelope is versioned and length-delimited so it remains unambiguous across
process restarts and Win32 HGLOBAL padding. After `OleFlushClipboard` (which
legitimately releases in-process OLE ownership), the client verifies that
receipt in a fresh system clipboard snapshot while the clipboard sequence
remains stable. The same sequence is checked again in the final synchronous
input commit. Code must not require in-process ownership after the flush.

## Platform privacy markers

- macOS honors concealed, transient, and autogenerated pasteboard types and
  excludes configured bundle identifiers.
- Windows honors `ExcludeClipboardContentFromMonitorProcessing`,
  `CanIncludeInClipboardHistory = 0`, and `CanUploadToCloudClipboard = 0`, and
  excludes configured process names.
- Windows history metadata and image blobs are encrypted with DPAPI CurrentUser.
  Settings that contain no clipboard payload may remain plain local JSON.

## Manual validation

Automated tests cover the normalization, store, persistence, and paste state
machine. Before release, each operating system still needs an interactive test
for clipboard ownership races, global shortcuts, focus restoration, tray/menu
behavior, multi-monitor scaling, and unsigned-install security prompts.
